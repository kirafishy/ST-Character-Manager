# AI 概览与标签生成 Prompt 优化设计

## 概述

优化 AI 概览与标签生成的 Prompt，解决以下问题：
1. 标签选择缺乏优先级规则，未能体现角色核心特征
2. 存在语义相近标签重复输出（如 同事/职场、傲娇/口是心非）
3. 缺乏关键分级标签（如 SFW/NSFW）的优先判定机制
4. 允许 AI 自创标签，导致标签库膨胀

## 需求分析

### 当前问题

| 问题 | 描述 | 影响 |
|------|------|------|
| 标签无优先级 | 特征标签与分级标签混选 | 难以快速筛选角色 |
| 语义重复 | 同一概念输出多个近义词 | 标签冗余、筛选困难 |
| 分级缺失 | SFW/NSFW 等关键分级不明确 | 用户体验风险 |
| 标签膨胀 | AI 可自创新标签 | 标签库混乱 |

### 用户期望

1. **分级优先**：必须先判断关键分级标签（如 SFW/NSFW），再补充特征标签
2. **白名单约束**：标签仅能从系统标签库中选择，禁止新造标签
3. **概念簇去重**：同一语义簇最多保留 1 个标签
4. **宁缺毋滥**：只输出高置信标签，允许少于上限或空数组

## 设计方案

### 1. 目标与判定规则

| 规则 | 描述 |
|------|------|
| 规则 1 - 分级优先 | 标签必须"先分级、后特征"，先判断关键分级标签（如内容分级），信息不足则不输出分级标签 |
| 规则 2 - 白名单约束 | 标签仅能从系统标签库中选择，禁止新造标签 |
| 规则 3 - 概念簇去重 | 同一语义簇最多保留 1 个标签（如 同事/职场、傲娇/口是心非 只能选其一） |
| 规则 4 - 宁缺毋滥 | 只输出高置信标签，允许少于上限或空数组，不为凑数降低准确性 |
| 规则 5 - 概览独立 | 概览文本继续保持精炼（150字以内），不因标签规则变化而扩写 |

### 2. Prompt 结构改造

#### 2.1 执行顺序指令

在 [`buildOverviewPrompt()`](../../ai-overview/prompt-builder.js:14) 与 [`buildBatchOverviewPrompt()`](../../ai-overview/prompt-builder.js:53) 中统一加入执行顺序指令：

```
[标签生成顺序]
1. 先判定分级标签：仅在证据充分时输出（如内容分级 SFW/NSFW）
2. 再筛选特征标签：仅从[系统标签库]中选择匹配标签
3. 最后做去重与裁剪：同一语义簇最多保留 1 个标签，按置信度排序后裁剪到上限
```

#### 2.2 硬约束段

新增硬约束段文字：

```
[硬性约束]
- 禁止创造新标签，只能从[系统标签库]中选择
- 不确定就不打标签，宁缺毋滥
- 标签数组可以为空或少于上限
- 若存在冲突候选（语义相近），保留区分度更高者
- 分级标签最多 1 个，仅当证据充分时输出
```

#### 2.4 Prompt 模板示例（批量）

```javascript
export function buildBatchOverviewPrompt(cardDataList, systemTags, forceGenerateTags = false) {
    const charactersSection = cardDataList.map((card, index) => {
        return `

--- 角色 ${index + 1} (fileName: "${card.fileName}") ---
${buildCharacterDataSection(card)}`;
    }).join('\n');
    
    const maxTags = state.settings.aiMaxTags || 5;
    
    return `你是一位专业的角色卡分析师。请分析以下${cardDataList.length}个角色卡数据，为每个角色生成概览和标签。

[角色卡列表]${charactersSection}

[任务要求]
1. 为每个角色生成概览：150字以内，精炼概括角色核心特征
2. 为每个角色生成标签：最多${maxTags}个，仅从[系统标签库]中选择匹配标签

[标签生成顺序]
1. 先判定分级标签：仅在证据充分时输出（如内容分级 SFW/NSFW）
2. 再筛选特征标签：仅从[系统标签库]中选择匹配标签
3. 最后做去重与裁剪：同一语义簇最多保留 1 个标签，按置信度排序后裁剪到上限

[硬性约束]
- 禁止创造新标签，只能从[系统标签库]中选择
- 不确定就不打标签，宁缺毋滥
- 标签数组可以为空或少于上限
- 若存在冲突候选（语义相近），保留区分度更高者
- 分级标签最多 1 个，仅当证据充分时输出

[系统标签库]
${JSON.stringify(systemTags)}

[回复格式] 严格仅返回JSON，不要markdown标记。主格式为 {"results":[...]}，若无法返回包裹格式则纯数组 [...] 也可接受：
{
  "results": [
    {"fileName": "角色1的fileName", "summary": "...", "tags": ["标签1", "标签2"]},
    {"fileName": "角色2的fileName", "summary": "...", "tags": ["标签1"]}
  ]
}
或回退格式：
[
  {"fileName": "角色1的fileName", "summary": "...", "tags": ["标签1", "标签2"]},
  {"fileName": "角色2的fileName", "summary": "...", "tags": ["标签1"]}
]

[字段约束] 必须使用以下键名：
- fileName: 角色文件名（用于匹配）
- summary: 概览内容（必填）
- tags: 标签数组（可选，可为空）`;
}
```

### 3. 输出格式与兼容策略

为保持最小改动，设计采用以下兼容策略：

| 项目 | 策略 |
|------|------|
| JSON 字段 | 保持现有字段不变，`{"summary": "...", "tags": [...]}` 与批量 `results` 格式 |
| 解析器 | 不修改 [`result-parser.js`](../../ai-overview/result-parser.js) 的解析协议 |
| 改动范围 | 仅修改 Prompt 内容，不改动代码逻辑 |

### 4. 验收标准与失败兜底

#### 4.1 验收标准

| 编号 | 标准 | 验证方式 |
|------|------|----------|
| 1 | 输出标签全部来自系统标签库（零新造词） | 检查输出标签是否全部存在于 systemTags |
| 2 | 同一语义簇不重复 | 人工抽样检查（同事/职场、傲娇/口是心非 等） |
| 3 | 关键分级先判定，证据不足时不输出分级标签 | 检查分级标签的准确性 |
| 4 | 标签允许为空或少于上限，不为凑数降低准确性 | 验证标签数量分布 |

#### 4.2 失败兜底

若模型输出不满足规则（如输出新造标签），由现有解析流程按空数组处理：
- 解析器继续正常解析 JSON
- 不额外扩展字段
- 用户可通过 UI 手动补充标签

## 风险评估

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 模型忽略约束输出新标签 | 中 | 低 | 解析器不报错，用户可手动补充 |
| 概念簇判定不一致 | 低 | 低 | Prompt 中给出示例 |
| 分级标签误判 | 低 | 中 | 强调"证据充分时输出"，允许不输出 |

## 测试要点

1. **白名单约束验证**：选择不同角色卡，验证输出标签是否全部在系统标签库中
2. **概念簇去重验证**：使用有明显语义相近标签的角色，验证输出不重复
3. **分级优先验证**：验证 SFW/NSFW 等分级标签是否优先判定
4. **宁缺毋滥验证**：使用信息不足的角色卡，验证标签数量是否少于上限或为空
