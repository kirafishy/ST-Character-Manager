# 设置页下拉框防撑宽布局修复设计

## 1. 背景与问题

在设置界面的 AI API 配置区域，点击“连接”后会动态写入模型列表。由于模型 ID 可能较长，当前下拉框在 `width: auto` 与缺少收缩约束的布局下会被内容撑宽，导致同排按钮和右侧元素被挤出容器，出现明显 UI 破版。

该问题并不只存在于模型下拉，设置页其他下拉在长选项文本场景下也存在同类风险。

## 2. 目标与非目标

### 2.1 目标

1. 统一修复设置页所有下拉的防撑宽行为。
2. 保持当前功能逻辑不变，仅调整布局与样式。
3. 模型区“连接”按钮保持贴右显示。
4. “已获取 X 个模型 / 连接失败”状态文案固定到按钮下一行。

### 2.2 非目标

1. 不修改 `fetch /models` 的请求与解析逻辑。
2. 不引入新依赖或新组件库。
3. 不改动设置页以外模块的布局行为。

## 3. 方案对比

### 方案 A：仅补丁下拉本体样式

- 做法：只为设置页 `select.cm-select-input` 添加 `max-width / min-width / ellipsis`。
- 优点：改动最小。
- 缺点：无法彻底处理“同排按钮 + 下拉”的容器级挤压关系，按钮贴右问题不稳定。

### 方案 B：统一布局约束 + 下拉截断（选定）

- 做法：
  - 为设置行右侧控件区建立可收缩 flex 约束。
  - 下拉统一允许收缩并截断显示。
  - 模型状态文案改为独占下一行。
- 优点：系统性解决下拉撑宽与按钮错位，兼容长文本场景。
- 缺点：样式规则比方案 A 稍多。

### 方案 C：裁剪 option 文本

- 做法：在渲染阶段裁剪模型名后写入 `option`。
- 优点：视觉可控。
- 缺点：破坏数据可读性与可复制性，且无法泛化到其他设置项。

## 4. 选定设计

采用方案 B，并限定在设置页作用域内生效。

### 4.1 结构与作用域

1. 以 `.cm-settings-container` 为作用域，避免影响其他页面。
2. 设置项行维持现有两列结构：左侧标签、右侧控件。
3. 右侧控件区统一为可收缩布局容器。

### 4.2 样式策略

1. 右侧控件区：`flex: 1; min-width: 0; max-width: 100%`。
2. 设置页下拉：
   - `min-width: 0`
   - `max-width: 100%`
   - `overflow: hidden`
   - `text-overflow: ellipsis`
   - `white-space: nowrap`
3. 模型行内部容器：下拉可收缩，按钮 `flex-shrink: 0` 保持贴右。
4. 模型状态文案：独占下一行 `width: 100%`，与按钮垂直分离。

### 4.3 行为保持

1. “连接中 / 已获取 / 失败”文案与状态切换逻辑保持现状。
2. 模型列表动态注入逻辑保持现状。

## 5. 兼容性与风险

## 5.1 兼容性

1. 仅使用标准 CSS flex 能力，兼容当前运行环境。
2. 对短文本场景无明显视觉变化。

### 5.2 风险与缓解

1. 风险：某些带内联宽度的下拉可能出现显示差异。
   - 缓解：规则放在设置页作用域内，并保留内联 `max-width` 的优先约束。
2. 风险：状态文案换行后造成行高变化。
   - 缓解：限制字号和外边距，保证节奏一致。

## 6. 验收标准

1. 点击“连接”后，长模型名不会再撑破设置行。
2. “连接”按钮保持贴右显示。
3. “已获取 X 个模型 / 连接失败”固定在按钮下一行。
4. 设置页其他下拉在长文本情况下不会挤出容器。

## 7. 实施范围

1. `style.css`：新增/调整设置页作用域的布局与下拉防溢出规则。
2. `settings.js`：仅在必要时补充最小结构 class（若纯 CSS 选择器可达则不改）。
